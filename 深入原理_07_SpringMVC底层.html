二、DispatcherServlet 请求处理流程

1. doDispatch() 完整流程

1

检查文件上传

checkMultipart() → 如果是multipart请求，包装为MultipartHttpServletRequest

2

获取Handler

getHandler() → 通过HandlerMapping找到HandlerExecutionChain

包含：Handler + Interceptor链
3

获取HandlerAdapter

getHandlerAdapter() → 找到能执行该Handler的Adapter

支持：RequestMapping、HttpRequestHandler、SimpleController
4

执行拦截器前置处理

applyPreHandle() → 遍历执行所有Interceptor.preHandle()

任意一个返回false则终止请求
5

执行Handler

ha.handle() → HandlerAdapter执行Controller方法

参数解析 → 方法执行 → 返回值处理
6

执行拦截器后置处理

applyPostHandle() → 遍历执行所有Interceptor.postHandle()

逆序执行（从最后一个Interceptor开始）
7

处理结果

processDispatchResult() → 视图渲染或异常处理

ModelAndView → ViewResolver → View.render()
8

执行拦截器完成后处理

triggerAfterCompletion() → 无论成功或异常都会执行

逆序执行，用于资源清理
9

清理资源

cleanupMultipart() → 清理文件上传临时资源

2. 源码实现

// applyPreHandle() - 正序执行
boolean applyPreHandle(HttpServletRequest request, HttpServletResponse response) {
    HandlerInterceptor[] interceptors = getInterceptors();
    for (int i = 0; i < interceptors.length; i++) {
        HandlerInterceptor interceptor = interceptors[i];
        if (!interceptor.preHandle(request, response, this.handler)) {
            triggerAfterCompletion(request, response, null);
            return false;  // 终止请求
        }
        this.interceptorIndex = i;  // 记录执行到的位置
    }
    return true;
}

// applyPostHandle() - 逆序执行
void applyPostHandle(HttpServletRequest request, HttpServletResponse response, ModelAndView mv) {
    HandlerInterceptor[] interceptors = getInterceptors();
    for (int i = interceptors.length - 1; i >= 0; i--) {
        interceptors[i].postHandle(request, response, this.handler, mv);
    }
}

// triggerAfterCompletion() - 逆序执行（只执行已通过的）
void triggerAfterCompletion(HttpServletRequest request, HttpServletResponse response, Exception ex) {
    HandlerInterceptor[] interceptors = getInterceptors();
    for (int i = this.interceptorIndex; i >= 0; i--) {
        interceptors[i].afterCompletion(request, response, this.handler, ex);
    }
}

3. @ControllerAdvice 原理

@ControllerAdvice 是全局异常处理的核心：

初始化扫描：
1. 扫描所有标注@ControllerAdvice的Bean
2. 提取basePackages、annotations等限定条件
3. 检查是否匹配当前Controller
4. 缓存ExceptionHandler方法

匹配逻辑：
- basePackages：只处理指定包下的Controller
- annotations：只处理带指定注解的Controller
- assignableTypes：只处理指定类型的Controller
- 无限定：处理所有Controller

执行顺序：
1. Controller自身的@ExceptionHandler（优先）
2. ControllerAdvice的@ExceptionHandler（其次）
3. 默认异常处理（最后）

九、面试高频问题

Q1: SpringMVC请求处理完整流程？

回答要点：

1. 用户发送请求到DispatcherServlet
2. DispatcherServlet调用getHandler()获取HandlerExecutionChain
   - 包含Handler + Interceptor链
3. getHandlerAdapter()获取能执行Handler的Adapter
4. 执行Interceptor.preHandle()（正序）
5. HandlerAdapter.handle()执行Controller方法
   - 参数解析：ArgumentResolver
   - 方法执行：反射调用
   - 返回值处理：ReturnValueHandler
6. 执行Interceptor.postHandle()（逆序）
7. processDispatchResult()处理结果
   - ViewResolver解析视图
   - View.render()渲染
8. Interceptor.afterCompletion()（逆序，总是执行）

核心组件：
- DispatcherServlet：中央控制器
- HandlerMapping：请求映射
- HandlerAdapter：方法执行
- ViewResolver：视图解析

Q2: HandlerMapping如何找到对应的Handler？

回答要点：

1. RequestMappingHandlerMapping初始化
   - 扫描所有@Controller/@RestController
   - 提取@RequestMapping信息
   - 创建RequestMappingInfo（URL、Method、Params等）
   - 注册到MappingRegistry

2. 请求到达时
   - 遍历所有HandlerMapping
   - 调用getHandlerInternal()
   - lookupHandlerMethod()匹配条件
   - 返回HandlerExecutionChain

3. 匹配优先级
   - 精确匹配 > 通配符匹配
   - HTTP方法匹配
   - 参数/Header匹配

Q3: 参数是如何解析的？

回答要点：

1. HandlerAdapter执行时
   - 获取方法参数数组
   - 遍历每个参数

2. 找到对应的ArgumentResolver
   - supportsParameter()判断是否支持
   - resolveArgument()解析参数值

3. 常见解析器
   - @RequestParam：request.getParameter()
   - @PathVariable：URI模板变量
   - @RequestBody：HttpMessageConverter反序列化
   - @ModelAttribute：创建对象+属性绑定

4. 参数绑定流程
   - 创建目标对象
   - 获取请求参数
   - 通过setter方法注入
   - 类型转换（String→目标类型）

Q4: @ResponseBody如何工作？

回答要点：

1. 返回值处理器
   - RequestResponseBodyMethodProcessor

2. 选择MessageConverter
   - 根据Content-Type判断
   - 根据返回值类型判断
   - canWrite()确认支持

3. 序列化输出
   - write()方法执行
   - Jackson将对象转JSON
   - 写入Response body

4. 流程
   方法返回 → handleReturnValue() →
   选择Converter → write() → 输出到响应

Q5: 拦截器和过滤器的区别？

回答要点：

| 特性 | Filter | Interceptor |
|------|--------|-------------|
| 所属 | Servlet容器 | SpringMVC |
| 作用范围 | 所有请求 | 只处理进入DispatcherServlet的请求 |
| 执行时机 | DispatcherServlet之前 | Handler执行前后 |
| 依赖注入 | 不支持（需手动） | 支持Spring注入 |
| 获取信息 | 只有Request/Response | 可获取Handler、ModelAndView |

执行顺序：
Filter.before → Interceptor.preHandle → Handler →
Interceptor.postHandle → View.render →
Interceptor.afterCompletion → Filter.after

应用场景：
Filter：编码转换、安全校验、日志记录
Interceptor：权限校验、日志、性能监控
