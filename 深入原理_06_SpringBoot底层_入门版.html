3. 你每天用的注解，到底干了什么

@SpringBootApplication 这个注解

你每个项目都会写这个，但你可能不知道它其实是三个注解的组合：

@SpringBootApplication =
    @SpringBootConfiguration  // 等于 @Configuration，标记这是个配置类
    + @EnableAutoConfiguration // 开启自动配置（核心！）
    + @ComponentScan           // 自动扫描你写的组件
翻译成人话：
  • @Configuration：告诉Spring"这个类里有Bean定义"
  • @EnableAutoConfiguration：告诉Spring"根据我加的依赖，自动帮我配置"
  • @ComponentScan：告诉Spring"去扫描我项目里的所有组件"
application.yml 里的配置

你写个 server.port: 8080，SpringBoot怎么知道要改端口？

答案是：有个叫 ServerProperties 的类，上面标注了：

@ConfigurationProperties(prefix = "server")
public class ServerProperties {
    private Integer port = 8080;  // 默认8080
    // setter方法
}

SpringBoot自动把 server.port 的值注入到这个类的 port 字段里。

然后Tomcat启动时读取这个值，就改成8080了。

@Autowired 怎么自动注入的？

你写个 @Autowired private UserService userService;，怎么就自动有值了？

过程是这样的：

  1. Spring扫描到你的Controller，发现它需要UserService
  2. Spring去容器里找UserService这个Bean
  3. 找到了，通过反射设置到你的Controller里
  4. 没找到？报错：NoSuchBeanDefinitionException

二、Level 2：和传统Spring对比理解

理解级 - 知道为什么这么设计

1. 自动配置：SpringBoot的灵魂

问题：我加了个mysql依赖，数据库连接怎么就有了？

传统Spring做法：

<!-- applicationContext.xml -->
<bean id="dataSource" class="com.zaxxer.hikari.HikariDataSource">
    <property name="driverClassName" value="com.mysql.cj.jdbc.Driver"/>
    <property name="url" value="jdbc:mysql://localhost:3306/mydb"/>
    <property name="username" value="root"/>
    <property name="password" value="123456"/>
</bean>

SpringBoot做法：

# application.yml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/mydb
    username: root
    password: 123456

为什么SpringBoot能自动配置？

因为有个叫 DataSourceAutoConfiguration 的配置类，它干了这些事：

  1. 检查你项目里有没有DataSource相关的依赖（mysql、hikari等）
  2. 如果有，就自动创建一个DataSource Bean
  3. 从application.yml读取配置，注入到这个Bean里

一句话：你只管加依赖、写配置，SpringBoot帮你创建Bean。

2. Starter：依赖管理的魔法

问题：为什么加个starter-web就够了，不用一个个加依赖？

看看 spring-boot-starter-web 的pom文件：

<dependencies>
    <dependency>spring-boot-starter</dependency>      // 核心starter
    <dependency>spring-web</dependency>             // Spring Web
    <dependency>spring-webmvc</dependency>         // Spring MVC
    <dependency>spring-boot-starter-tomcat</dependency> // 内嵌Tomcat
    <dependency>spring-boot-starter-json</dependency>   // Jackson
    ...
</dependencies>

Starter就是一个"依赖包"，帮你把相关依赖都打包好了。

比如你要用Web功能，就加web-starter，它帮你带了：

  • Spring WebMVC
  • 内嵌Tomcat
  • JSON处理Jackson
  • 验证功能
  • ...等等

好处：不用担心版本冲突，不用一个个查依赖，一站式搞定。

3. 内嵌Tomcat：不部署也能跑

问题：为什么main方法就能启动Web服务？

传统做法：

  1. 打包成war
  2. 下载安装Tomcat
  3. 把war放到Tomcat的webapps目录
  4. 启动Tomcat

SpringBoot做法：

  1. SpringBoot把Tomcat打成jar包放到你的项目里
  2. main方法启动时，创建一个Tomcat实例
  3. 把你的项目部署到这个内嵌Tomcat
  4. Tomcat开始监听8080端口
// SpringBoot启动时做的事（简化版）
public void run() {
    // 1. 创建Tomcat
    Tomcat tomcat = new Tomcat();

    // 2. 设置端口
    tomcat.setPort(8080);

    // 3. 添加你的项目
    tomcat.addWebapp("/", new File("src/main/webapp"));

    // 4. 启动Tomcat
    tomcat.start();
}

一句话：SpringBoot自带了Tomcat，启动时把它跑起来。

三、Level 3：核心原理讲解

原理级 - 理解底层工作机制

1. 启动流程：一个main方法的背后

🚀

1. 创建SpringApplication对象

推断这是Web项目还是普通项目，加载一些监听器和初始化器

🔍

2. 执行run()方法启动

准备环境，发布启动事件，创建ApplicationContext容器

⚙️

3. 执行自动配置（核心步骤）

读取spring.factories，加载所有自动配置类，根据条件决定是否生效

📦

4. 创建所有Bean

扫描你的组件，加上自动配置的Bean，全部创建好放入容器

✅

5. 启动内嵌Tomcat

如果是Web项目，启动内嵌的Tomcat，监听端口

关键：第3步"自动配置"怎么工作的

核心文件：spring.factories

在spring-boot-autoconfigure这个jar包里，有个文件：

META-INF/spring.factories：

org.springframework.boot.autoconfigure.EnableAutoConfiguration=
org.springframework.boot.autoconfigure.web.servlet.WebMvcAutoConfiguration,
org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration,
org.springframework.boot.autoconfigure.data.redis.RedisAutoConfiguration,
...（几十上百个配置类）

SpringBoot启动时会：

  1. 读取这个文件，拿到所有配置类名单
  2. 逐个检查每个配置类"是否应该生效"
  3. 生效的就执行，创建相应的Bean

2. 条件注解：自动配置的开关

配置类上的条件注解

看一个自动配置类的源码：

@Configuration
@ConditionalOnClass(DataSource.class)  // 条件1：类路径有DataSource
@EnableConfigurationProperties(DataSourceProperties.class)
public class DataSourceAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean  // 条件2：容器里没有自定义的DataSource
    public DataSource dataSource(DataSourceProperties props) {
        return props.initializeDataSourceBuilder().build();
    }
}

翻译成流程：

  1. @ConditionalOnClass(DataSource.class)
    → 检查你项目里有没有DataSource相关的类（mysql驱动等）
    → 有才继续，没有跳过这个配置
  2. @ConditionalOnMissingBean
    → 检查容器里有没有用户自己定义的DataSource
    → 没有才创建默认的，有了就不创建（让用户自定义的生效）

这就是"约定优于配置"的体现：

你没自己配 → SpringBoot帮你配一个默认的
你自己配了 → SpringBoot就不配了，用你的

3. 常见条件注解一览

注解
检查什么
@ConditionalOnClass
类路径里有没有某个类
@ConditionalOnMissingClass
类路径里没有某个类
@ConditionalOnBean
容器里有没有某个Bean
@ConditionalOnMissingBean
容器里没有某个Bean（最常用）

四、Level 4：面试深入理解

源码级 - 面试追问时能说清

1. 自动配置完整流程（源码视角）

从@EnableAutoConfiguration说起
@EnableAutoConfiguration
@Import(AutoConfigurationImportSelector.class)
public @interface EnableAutoConfiguration { }

AutoConfigurationImportSelector干的事：

public String[] selectImports() {
    // 1. 读取spring.factories
    List<String> configurations = SpringFactoriesLoader
        .loadFactoryNames(EnableAutoConfiguration.class, classLoader);

    // 2. 去重
    configurations = removeDuplicates(configurations);

    // 3. 排除（通过exclude属性或配置）
    configurations = filter(configurations, exclusions);

    // 4. 过滤（检查条件注解）
    configurations = filter(configurations,
        new OnClassCondition(),    // 检查@ConditionalOnClass
        new OnBeanCondition(),     // 检查@ConditionalOnBean
        new OnPropertyCondition()  // 检查@ConditionalOnProperty
    );

    // 5. 返回要加载的配置类
    return configurations.toArray(new String[0]);
}

2. refresh()方法做了什么

ApplicationContext.refresh() 12步骤

这是Spring容器启动的核心方法：

refresh() {
    1. prepareRefresh()        // 准备工作
    2. obtainFreshBeanFactory()// 创建/获取BeanFactory
    3. prepareBeanFactory()    // 配置BeanFactory

    4. invokeBeanFactoryPostProcessors() // 执行BFPP（关键！）
       // 这里会执行ConfigurationClassPostProcessor
       // 解析@Configuration、@ComponentScan、@Import
       // 加载所有BeanDefinition（包括自动配置类）

    5. registerBeanPostProcessors() // 注册BPP
    6. initMessageSource()          // 国际化
    7. initApplicationEventMulticaster() // 事件广播
    8. onRefresh()                  // 子类扩展（Web容器在此启动）
    9. registerListeners()          // 注册监听器

    10. finishBeanFactoryInitialization() // 创建所有Bean
        // 这里把所有Bean都创建好，包括你的Controller、Service

    11. finishRefresh()             // 完成刷新
    12. 发布ContextRefreshedEvent   // 容器就绪
}

面试重点：第4步和第10步

  • 第4步：加载所有配置类，解析Bean定义
  • 第10步：真正创建Bean对象

3. 面试常见问题回答

Q1: SpringBoot自动配置原理？

回答要点（分层次说）：

  1. 入口：@EnableAutoConfiguration注解
  2. 机制：通过@Import导入AutoConfigurationImportSelector
  3. 加载：读取META-INF/spring.factories获取所有自动配置类
  4. 过滤：根据条件注解（@ConditionalOnXxx）判断是否生效
  5. 生效：满足条件的配置类执行，创建相应Bean

举个例子：

我加了mysql依赖 → spring.factories里有DataSourceAutoConfiguration → 检查@ConditionalOnClass(DataSource.class)有这个类 → 检查@ConditionalOnMissingBean没有自定义DataSource → 创建默认的HikariDataSource

Q2: SpringBoot启动流程？

简化版回答：

  1. new SpringApplication() - 推断类型、加载初始化器和监听器
  2. run() - 准备环境、发布事件
  3. 创建ApplicationContext容器
  4. prepareContext() - 准备上下文
  5. refreshContext() - 刷新容器（核心：自动配置+创建Bean）
  6. 如果是Web项目，启动内嵌Tomcat
  7. 发布ApplicationReadyEvent - 启动完成

深入版回答：

refresh()方法内部会执行ConfigurationClassPostProcessor，它会解析@SpringBootApplication， 处理@EnableAutoConfiguration，触发自动配置流程，然后finishBeanFactoryInitialization() 会创建所有Bean。

Q3: @ConditionalOnMissingBean为什么重要？

它实现了"用户配置优先"的设计理念：

// SpringBoot自动配置类
@Bean
@ConditionalOnMissingBean
public DataSource dataSource() {
    return new HikariDataSource();  // 默认实现
}

流程：

  1. SpringBoot准备创建默认DataSource
  2. 先检查容器里有没有用户自定义的DataSource
  3. 有 → 不创建默认的，用用户的
  4. 没有 → 创建默认的HikariDataSource

好处：用户可以随时覆盖默认配置，而不影响SpringBoot的自动配置机制。

Q4: 如何自定义一个Starter？

三个步骤：

Step 1: 创建autoconfigure模块

// MyServiceAutoConfiguration.java
@Configuration
@ConditionalOnClass(MyService.class)
@EnableConfigurationProperties(MyServiceProperties.class)
public class MyServiceAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean
    public MyService myService(MyServiceProperties props) {
        return new MyService(props.getHost(), props.getPort());
    }
}

// MyServiceProperties.java
@ConfigurationProperties(prefix = "my-service")
public class MyServiceProperties {
    private String host = "localhost";
    private Integer port = 8080;
}

Step 2: 创建spring.factories

META-INF/spring.factories：
org.springframework.boot.autoconfigure.EnableAutoConfiguration=
com.example.MyServiceAutoConfiguration

Step 3: 创建starter模块（依赖autoconfigure）

<dependency>
    <groupId>com.example</groupId>
    <artifactId>my-service-spring-boot-autoconfigure</artifactId>
</dependency>

用户使用时：

// 1. 加依赖
<dependency>
    <groupId>com.example</groupId>
    <artifactId>my-service-spring-boot-starter</artifactId>
</dependency>

// 2. 写配置
my-service.host=192.168.1.1
my-service.port=9090

// 3. 直接用
@Autowired
private MyService myService;
