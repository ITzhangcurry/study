深入原理：代理模式详解

一、什么是代理模式

1. 生活中的代理

你（客户）
想买演唱会门票
→
黄牛（代理）
帮你买票、加价收费
→
售票处（目标）
真正卖票的地方

代理模式的本质：不直接访问目标对象，而是通过代理对象间接访问，代理对象可以在访问前后做一些额外的事情。

2. 程序中的代理结构

调用方
调用proxy.method()
→
代理对象
增强逻辑 + 调用target
→
目标对象
执行真实业务

3. 代理模式的用途

常见应用场景
  • 增强功能 - 添加日志、性能监控、事务管理等
  • 控制访问 - 权限检查、延迟加载、远程调用
  • 隐藏实现 - 调用方只知道代理，不知道真实实现

二、静态代理

1. 什么是静态代理

静态代理：代理类在代码编译时就确定，由程序员手动编写或工具生成。

2. 静态代理实现步骤

1
定义接口 - 目标对象和代理对象都实现同一个接口
2
创建目标类 - 实现接口，编写真实业务逻辑
3
创建代理类 - 实现接口，持有目标对象引用
4
在代理类中增强 - 调用目标方法前后添加额外逻辑

3. 静态代理代码示例

接口 + 目标类
// 1. 定义接口
public interface UserService {
    void addUser(String name);
    void deleteUser(String id);
}

// 2. 目标类 - 真实业务
public class UserServiceImpl implements UserService {
    @Override
    public void addUser(String name) {
        System.out.println("添加用户：" + name);
    }

    @Override
    public void deleteUser(String id) {
        System.out.println("删除用户：" + id);
    }
}
静态代理类
// 3. 静态代理类
public class UserServiceProxy implements UserService {

    private UserService target;  // 持有目标对象

    public UserServiceProxy(UserService target) {
        this.target = target;
    }

    @Override
    public void addUser(String name) {
        System.out.println("[静态代理] 开始添加用户");
        target.addUser(name);  // 调用目标方法
        System.out.println("[静态代理] 添加用户完成");
    }

    @Override
    public void deleteUser(String id) {
        System.out.println("[静态代理] 开始删除用户");
        target.deleteUser(id);
        System.out.println("[静态代理] 删除用户完成");
    }
}

4. 使用方式

// 创建目标对象
UserService target = new UserServiceImpl();

// 创建代理对象（传入目标）
UserService proxy = new UserServiceProxy(target);

// 通过代理调用
proxy.addUser("张三");

// 输出：
// [静态代理] 开始添加用户
// 添加用户：张三
// [静态代理] 添加用户完成

三、动态代理

1. 什么是动态代理

动态代理：代理类在运行时动态生成，不需要程序员手动编写。一个代理类可以代理多个目标对象。

动态代理的核心优势
  • 一个代理类可以代理任意接口的实现类
  • 接口新增方法，无需修改代理代码
  • 代理逻辑可以动态配置

2. Java中的两种动态代理

JDK动态代理
  • Java原生支持，JDK自带
  • 基于接口，目标类必须实现接口
  • 使用 java.lang.reflect.Proxy
  • 底层使用反射机制
// 生成代理对象
Proxy.newProxyInstance(
    classLoader,
    interfaces,    // 目标类实现的接口
    invocationHandler
);
CGLIB动态代理
  • 第三方库，需引入依赖
  • 基于类继承，目标类不需要接口
  • 使用 net.sf.cglib.proxy.Enhancer
  • 底层使用ASM生成字节码
// 生成代理对象
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(targetClass);  // 继承目标类
enhancer.setCallback(methodInterceptor);
enhancer.create();

3. JDK动态代理详解

核心类：InvocationHandler

public interface InvocationHandler {
    /**
     * 代理方法被调用时执行
     * @param proxy     代理对象本身
     * @param method    被调用的方法
     * @param args      方法参数
     * @return          方法返回值
     */
    Object invoke(Object proxy, Method method, Object[] args) throws Throwable;
}

JDK动态代理实现步骤

1
创建InvocationHandler实现类 - 在invoke方法中编写代理逻辑
2
调用Proxy.newProxyInstance() - 传入类加载器、接口数组、Handler
3
获得代理对象 - 动态生成的代理类实现了指定接口
4
通过代理调用方法 - 所有方法调用都会进入InvocationHandler.invoke()

JDK动态代理完整代码

// 1. 创建InvocationHandler
public class LogInvocationHandler implements InvocationHandler {

    private Object target;  // 目标对象

    public LogInvocationHandler(Object target) {
        this.target = target;
    }

    @Override
    public Object invoke(Object proxy, Method method, Object[] args) throws Throwable {
        // 增强逻辑 - 前置
        System.out.println("[JDK动态代理] 调用方法：" + method.getName());
        long start = System.currentTimeMillis();

        // 调用目标方法
        Object result = method.invoke(target, args);

        // 增强逻辑 - 后置
        long end = System.currentTimeMillis();
        System.out.println("[JDK动态代理] 耗时：" + (end - start) + "ms");

        return result;
    }
}

// 2. 创建代理对象
public class ProxyFactory {

    public static Object getProxy(Object target) {
        return Proxy.newProxyInstance(
            target.getClass().getClassLoader(),  // 类加载器
            target.getClass().getInterfaces(),    // 目标类实现的接口
            new LogInvocationHandler(target)      // InvocationHandler
        );
    }
}

// 3. 使用代理
UserService target = new UserServiceImpl();
UserService proxy = (UserService) ProxyFactory.getProxy(target);

proxy.addUser("张三");
// 输出：
// [JDK动态代理] 调用方法：addUser
// 添加用户：张三
// [JDK动态代理] 耗时：5ms

4. JDK动态代理底层原理

Proxy.newProxyInstance()做了什么？

Proxy.newProxyInstance() 的核心步骤：

1. 检查接口是否合法
   - interfaces不能为空
   - interfaces必须都是接口类型

2. 获取或创建代理类
   - 先从缓存查找 proxyClassCache
   - 没有则生成新的代理类

3. 生成代理类的字节码
   - 代理类命名：$Proxy0、$Proxy1...
   - 代理类实现所有传入的接口
   - 每个接口方法内部调用 InvocationHandler.invoke()

4. 创建代理对象实例
   - 通过反射创建代理类对象
   - 将 InvocationHandler 传入代理对象

生成的代理类结构（伪代码）

// JDK动态生成的代理类（简化版）
public class $Proxy0 extends Proxy implements UserService {

    private static Method m_addUser;
    private static Method m_deleteUser;

    static {
        // 通过反射获取接口方法
        m_addUser = UserService.class.getMethod("addUser", String.class);
        m_deleteUser = UserService.class.getMethod("deleteUser", String.class);
    }

    public $Proxy0(InvocationHandler h) {
        super(h);  // 保存Handler到父类Proxy
    }

    @Override
    public void addUser(String name) {
        try {
            // 调用Handler的invoke方法
            super.h.invoke(this, m_addUser, new Object[]{name});
        } catch (Throwable t) {
            throw new UndeclaredThrowableException(t);
        }
    }

    @Override
    public void deleteUser(String id) {
        try {
            super.h.invoke(this, m_deleteUser, new Object[]{id});
        } catch (Throwable t) {
            throw new UndeclaredThrowableException(t);
        }
    }
}
关键理解

JDK动态代理生成的类：继承Proxy + 实现目标接口

每个方法内部：直接调用 InvocationHandler.invoke()

这就是为什么目标类必须实现接口——因为代理类也要实现这个接口！

5. CGLIB动态代理详解

CGLIB原理

CGLIB（Code Generator Library）：
- 通过字节码技术生成目标类的子类
- 在子类中拦截父类方法调用
- 添加增强逻辑

核心：MethodInterceptor 接口

CGLIB动态代理代码

// 1. 实现MethodInterceptor
public class LogMethodInterceptor implements MethodInterceptor {

    @Override
    public Object intercept(Object obj, Method method, Object[] args,
                            MethodProxy proxy) throws Throwable {

        // 增强逻辑 - 前置
        System.out.println("[CGLIB代理] 调用方法：" + method.getName());

        // 调用目标方法（注意用proxy.invokeSuper）
        Object result = proxy.invokeSuper(obj, args);

        // 增强逻辑 - 后置
        System.out.println("[CGLIB代理] 方法执行完成");

        return result;
    }
}

// 2. 创建代理对象
public class CglibProxyFactory {

    public static Object getProxy(Class targetClass) {
        Enhancer enhancer = new Enhancer();
        enhancer.setSuperclass(targetClass);  // 设置父类（目标类）
        enhancer.setCallback(new LogMethodInterceptor());
        return enhancer.create();  // 创建代理对象
    }
}

// 3. 使用（目标类不需要实现接口）
public class UserService {  // 没有实现接口
    public void addUser(String name) {
        System.out.println("添加用户：" + name);
    }
}

UserService proxy = (UserService) CglibProxyFactory.getProxy(UserService.class);
proxy.addUser("张三");

CGLIB的限制

CGLIB无法代理的情况
  • final类 - 无法继承final类
  • final方法 - 无法覆盖final方法
  • static方法 - 静态方法不参与继承
  • private方法 - 私有方法子类不可见

五、Spring AOP中的代理选择

1. Spring如何选择代理方式

Spring AOP代理选择规则：

if (目标类实现了接口) {
    // 默认使用JDK动态代理
    // 可通过配置强制使用CGLIB
    useJdkDynamicProxy();
} else {
    // 目标类没有实现接口，只能用CGLIB
    useCglibProxy();
}

2. 配置代理方式

# application.yml
spring:
  aop:
    proxy-target-class: true  # 强制使用CGLIB（即使有接口）

// 或者注解方式
@EnableAspectJAutoProxy(proxyTargetClass = true)

3. Spring AOP代理创建流程

1
Bean初始化后 - AbstractAutoProxyCreator.postProcessAfterInitialization()
2
判断是否需要代理 - 检查是否有切面匹配该Bean
3
选择代理方式 - 根据目标类是否实现接口决定JDK或CGLIB
4
创建代理对象 - 返回代理对象替代原始Bean放入容器

六、面试高频问题

Q1: 静态代理和动态代理的区别？

回答要点：

1. 代理类创建时机
   - 静态：编译期确定，手动编写
   - 动态：运行时生成，反射/字节码技术

2. 代理类数量
   - 静态：一个接口对应一个代理类，类爆炸
   - 动态：一个Handler/Interceptor可代理任意类

3. 扩展性
   - 静态：接口新增方法，所有代理类都要修改
   - 动态：接口新增方法，无需修改代理逻辑

4. 使用场景
   - 静态：代理类较少、接口稳定时
   - 动态：AOP、RPC框架、Spring事务等

Q2: JDK动态代理为什么要求目标类实现接口？

回答要点：

根本原因：代理类要和目标类"长得一样"（有相同的方法）

JDK动态代理生成的类：
- 继承 java.lang.reflect.Proxy
- 实现传入的interfaces数组中的所有接口

因为Java不支持多继承，代理类已经继承了Proxy，
所以只能通过"实现接口"来获得目标类的方法签名。

如果目标类没实现接口，代理类就没法获得方法签名，
没法生成代理类。

对比CGLIB：
- 通过继承目标类获得方法签名
- 所以目标类不需要实现接口

Q3: JDK动态代理和CGLIB哪个性能更好？

回答要点：

JDK动态代理：
- 通过反射调用方法，有一定开销
- JDK8后反射性能优化，差距缩小

CGLIB：
- 通过FastClass机制，直接定位方法索引
- 避免反射开销，理论上性能更好
- 但生成字节码有开销，首次创建较慢

结论：
- JDK7之前：CGLIB明显更快
- JDK8之后：差距很小，JDK动态代理够用
- Spring默认JDK动态代理（有接口时），够用就行

实际：性能差异不是选型的关键，关键是目标类是否实现接口

Q4: Spring AOP为什么默认用JDK动态代理？

回答要点：

1. JDK动态代理是Java原生支持，无需依赖
   CGLIB是第三方库，需要引入

2. Spring的设计哲学：面向接口编程
   好的设计应该是接口+实现分离
   JDK动态代理正好鼓励这种设计

3. 性能差距在JDK8后很小
   不需要为了性能刻意选CGLIB

4. 只有目标类没接口时，才被迫用CGLIB
   这是最后的选择，不是默认选择

总结：Spring鼓励接口编程，JDK动态代理是自然选择

Q5: 代理模式在Spring中的应用？

回答要点：

1. Spring AOP
   - @Aspect切面通过代理实现方法拦截
   - 日志、权限、性能监控、事务管理

2. Spring事务管理
   - @Transactional通过代理实现事务拦截
   - 方法前后自动开启/提交/回滚事务

3. Spring缓存
   - @Cacheable通过代理实现缓存拦截
   - 先查缓存，缓存miss再执行方法

4. Spring远程调用
   - @RemoteService通过代理实现RPC
   - 代理对象封装网络通信细节

5. Spring懒加载
   - @Lazy通过代理延迟创建Bean
   - 首次使用时才真正创建

七、总结图

代理模式核心要点
静态代理 = 手写代理类，一个接口一个代理
JDK动态代理 = 反射生成代理类，要求目标类实现接口
CGLIB动态代理 = 字节码生成子类，不要求接口

Spring AOP选择规则：
有接口 → JDK动态代理（默认）
无接口 → CGLIB动态代理
