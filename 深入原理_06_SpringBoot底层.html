深入原理：SpringBoot 底层

一、SpringBoot 启动流程底层

1. SpringApplication.run() 整体流程

SpringApplication.run(source, args):

1. new SpringApplication(primarySources)
   - 推断应用类型（SERVLET/REACTIVE/NONE）
   - 加载 ApplicationContextInitializer
   - 加载 ApplicationListener
   - 推断主类

2. run(args)
   - StopWatch.start()
   - getRunListeners()：获取 SpringApplicationRunListener
   - listeners.starting()
   - prepareEnvironment()
   - prepareContext()
   - refreshContext()
   - afterRefresh()
   - listeners.finished()

2. 应用类型推断

WebApplicationType.deduceFromClasspath():

SERVLET（传统Web）:
- ClassUtils.isPresent("javax.servlet.Servlet")
- ClassUtils.isPresent("org.springframework.web.context.ConfigurableWebApplicationContext")

REACTIVE（响应式）:
- ClassUtils.isPresent("org.springframework.web.reactive.DispatcherHandler")
- 不存在 SERVLET 相关类

NONE（非Web）:
- 以上都不存在

3. ApplicationContext 创建

createApplicationContext():

SERVLET:
- AnnotationConfigServletWebServerApplicationContext
- 内嵌 Tomcat/Jetty/Undertow

REACTIVE:
- AnnotationConfigReactiveWebServerApplicationContext

NONE:
- AnnotationConfigApplicationContext

关键特性:
- 继承 GenericApplicationContext
- 内置 AnnotatedBeanDefinitionReader
- 内置 ClassPathBeanDefinitionScanner

4. refreshContext() 核心流程

AbstractApplicationContext.refresh():

1. prepareRefresh()
   - 初始化属性源
   - 验证必要属性

2. obtainFreshBeanFactory()
   - 刷新 BeanFactory
   - 如果存在则销毁重建

3. prepareBeanFactory(beanFactory)
   - 设置 BeanFactory 类加载器
   - 注册 Environment、SystemProperties、SystemEnvironment
   - 注册 ApplicationContextAwareProcessor

4. postProcessBeanFactory(beanFactory)
   - 子类扩展点

5. invokeBeanFactoryPostProcessors(beanFactory)
   - 执行 ConfigurationClassPostProcessor（关键）
   - 解析 @Configuration、@ComponentScan、@Import
   - 注册 BeanDefinition

6. registerBeanPostProcessors(beanFactory)
   - 注册所有 BeanPostProcessor

7. initMessageSource()
   - 国际化消息源

8. initApplicationEventMulticaster()
   - 事件广播器

9. onRefresh()
   - 子类扩展（Web容器在此启动）

10. registerListeners()
    - 注册 ApplicationListener

11. finishBeanFactoryInitialization(beanFactory)
    - 初始化非懒加载 Bean

12. finishRefresh()
    - 发布 ContextRefreshedEvent

5. 内嵌容器启动（onRefresh）

ServletWebServerApplicationContext.onRefresh():

1. createWebServer()
   - getWebServerFactory()：获取工厂
   - TomcatServletWebServerFactory
   - JettyServletWebServerFactory
   - UndertowServletWebServerFactory

2. TomcatServletWebServerFactory.getWebServer()
   - new Tomcat()
   - 设置 Connector（端口、协议）
   - 创建 StandardContext
   - 添加 ServletContainerInitializer
   - 启动 Tomcat

3. 关键配置
   - server.port
   - server.servlet.context-path
   - server.tomcat.max-threads

二、自动配置原理

1. @SpringBootApplication 组合注解

@SpringBootApplication:
    @SpringBootConfiguration      // 等同 @Configuration
    @EnableAutoConfiguration      // 自动配置核心
    @ComponentScan                // 组件扫描

@EnableAutoConfiguration:
    @Import(AutoConfigurationImportSelector.class)

2. AutoConfigurationImportSelector

selectImports():

1. getCandidateConfigurations()
   - SpringFactoriesLoader.loadFactoryNames()
   - 从 META-INF/spring.factories 加载
   - key = EnableAutoConfiguration.class.getName()
   - 返回自动配置类列表

2. 去重
   - removeDuplicates(configurations)

3. 排除
   - @SpringBootApplication(exclude)
   - spring.autoconfigure.exclude 配置

4. 过滤（核心）
   - AutoConfigurationImportFilter
   - OnClassCondition
   - OnBeanCondition
   - OnPropertyCondition
   - 不满足条件的配置被移除

5. 排序
   - @AutoConfigureOrder
   - @AutoConfigureBefore/@After

3. Spring.factories 文件解析

META-INF/spring.factories（spring-boot-autoconfigure）:

# Auto Configure
org.springframework.boot.autoconfigure.EnableAutoConfiguration=
org.springframework.boot.autoconfigure.web.servlet.WebMvcAutoConfiguration,
org.springframework.boot.autoconfigure.web.servlet.ServletWebServerFactoryAutoConfiguration,
org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration,
org.springframework.boot.autoconfigure.orm.jpa.HibernateJpaAutoConfiguration,
org.springframework.boot.autoconfigure.data.redis.RedisAutoConfiguration,
...

每个配置类都有条件注解控制是否生效

4. 条件注解原理

@ConditionalOnClass(DataSource.class)
- OnClassCondition.matches()
- ClassUtils.isPresent("javax.sql.DataSource")
- 检查类路径是否存在该类

@ConditionalOnBean(DataSource.class)
- OnBeanCondition.matches()
- BeanFactory.containsBeanDefinition("dataSource")
- 检查容器中是否已注册

@ConditionalOnMissingBean(DataSource.class)
- 检查容器中没有该 Bean
- 用于提供默认配置

@ConditionalOnProperty("spring.datasource.url")
- OnPropertyCondition.matches()
- Environment.containsProperty("spring.datasource.url")
- 检查配置文件是否存在该属性

@ConditionalOnWebApplication
- OnWebApplicationCondition.matches()
- 检查是否为 Web 应用

@ConditionalOnExpression("${feature.enabled}")
- SpEL 表达式评估

5. 配置类解析流程

ConfigurationClassPostProcessor.postProcessBeanDefinitionRegistry():

1. findCandidateComponents()
   - @Configuration
   - @Component (@Service, @Controller, @Repository)
   - @Import
   - @ImportResource
   - @PropertySource

2. parse(configurationClass)
   - 处理 @ComponentScan
   - 处理 @Import（关键）
   - 处理 @Bean 方法

3. processImports()
   - ImportSelector：调用 selectImports()
   - ImportBeanDefinitionRegistrar：调用 registerBeanDefinitions()
   - 普通 @Configuration：递归解析

4. loadBeanDefinitions()
   - 注册 BeanDefinition

6. 自动配置示例：DataSourceAutoConfiguration

@Configuration
@ConditionalOnClass({ DataSource.class, EmbeddedDatabaseType.class })
@EnableConfigurationProperties(DataSourceProperties.class)
@Import({ DataSourcePoolMetadataProvidersConfiguration.class })
public class DataSourceAutoConfiguration {

    @Configuration
    @Conditional(PooledDataSourceCondition.class)
    @ConditionalOnMissingBean({ DataSource.class, XADataSource.class })
    @Import({ HikariConfiguration.class, Tomcat.class, Dbcp2.class })
    static class PooledDataSourceConfiguration {
        // 创建连接池 DataSource
    }

    @Configuration
    @ConditionalOnMissingBean({ DataSource.class })
    @Conditional(EmbeddedDatabaseCondition.class)
    static class EmbeddedDataSourceConfiguration {
        // 创建嵌入式 DataSource（H2、HSQLDB）
    }
}

生效条件:
1. 类路径存在 DataSource.class
2. 存在连接池依赖（HikariCP、Tomcat JDBC）
3. 配置了 spring.datasource.url
4. 没有自定义 DataSource Bean

三、配置绑定原理

1. @ConfigurationProperties

@ConfigurationProperties(prefix = "server")
public class ServerProperties {
    private Integer port = 8080;
    private String address;
    // getter/setter
}

绑定机制:
1. Environment.getProperty("server.port")
2. 通过 setter 注入
3. 支持嵌套属性（server.tomcat.max-threads）
4. 支持 List/Map 类型

2. ConfigurationPropertiesBindingPostProcessor

postProcessBeforeInitialization():

1. 检查 @ConfigurationProperties 注解
2. 获取 Environment
3. 创建 RelaxedDataBinder
4. 绑定属性值

RelaxedDataBinder:
- 支持松散绑定
- server.port → serverPort
- server-port → serverPort
- SERVER_PORT → serverPort

3. @EnableConfigurationProperties

@EnableConfigurationProperties(ServerProperties.class)

作用:
1. 注册 ServerProperties Bean
2. 注册 ConfigurationPropertiesBindingPostProcessor
3. 确保 @ConfigurationProperties 生效

4. 配置属性校验

@ConfigurationProperties(prefix = "app")
@Validated
public class AppProperties {

    @NotBlank
    private String name;

    @Min(1)
    @Max(100)
    private Integer maxConnections;
}

校验时机:
- 属性绑定完成后
- 使用 JSR-303 验证器
- 验证失败抛出 BindValidationException

四、Starter 原理

1. Starter 结构

spring-boot-starter-web:
├── spring-boot-starter          // 基础 starter
│   ├── spring-boot
│   ├── spring-boot-autoconfigure
│   ├── spring-boot-starter-logging
│   └── spring-core
├── spring-web
├── spring-webmvc
├── spring-boot-starter-tomcat
├── jackson
└── spring-boot-starter-json

设计原则:
- starter 只负责依赖传递
- autoconfigure 负责自动配置
- 用户只需引入 starter

2. 自定义 Starter 开发

1. 创建 autoconfigure 模块
   ├── MyServiceAutoConfiguration.java
   ├── MyServiceProperties.java
   ├── META-INF/spring.factories
   └── META-INF/spring-configuration-metadata.json

2. 创建 starter 模块
   ├── pom.xml（依赖 autoconfigure）

3. spring.factories
   org.springframework.boot.autoconfigure.EnableAutoConfiguration=
   com.example.MyServiceAutoConfiguration

4. 自动配置类
   @Configuration
   @ConditionalOnClass(MyService.class)
   @EnableConfigurationProperties(MyServiceProperties.class)
   public class MyServiceAutoConfiguration {

       @Bean
       @ConditionalOnMissingBean
       public MyService myService(MyServiceProperties props) {
           return new MyService(props.getHost(), props.getPort());
       }
   }

5. 属性类
   @ConfigurationProperties(prefix = "my-service")
   public class MyServiceProperties {
       private String host = "localhost";
       private Integer port = 8080;
   }

3. spring-configuration-metadata.json

{
  "groups": [
    {
      "name": "my-service",
      "type": "com.example.MyServiceProperties"
    }
  ],
  "properties": [
    {
      "name": "my-service.host",
      "type": "java.lang.String",
      "description": "服务主机地址",
      "default-value": "localhost"
    },
    {
      "name": "my-service.port",
      "type": "java.lang.Integer",
      "description": "服务端口",
      "default-value": 8080
    }
  ]
}

作用:
- IDE 配置提示
- 配置文档生成
- 类型校验

五、Web 容器原理

1. Tomcat 启动流程

TomcatServletWebServerFactory.getWebServer():

1. new Tomcat()
   - 创建 Tomcat 实例

2. 设置基础目录
   - tomcat.setBaseDir(tempDir)

3. 创建 Connector
   - Connector connector = new Connector("HTTP/1.1")
   - connector.setPort(port)
   - connector.setProperty("maxThreads", maxThreads)

4. 创建 Context
   - StandardContext context = new StandardContext()
   - context.setPath(contextPath)
   - context.addLifecycleListener(new ContextConfig())

5. 添加 ServletContainerInitializer
   - TomcatStarter（实现 ServletContainerInitializer）
   - 注册 DispatcherServlet

6. 启动
   - tomcat.start()
   - await() 等待关闭

2. DispatcherServlet 注册

WebMvcAutoConfiguration.DispatcherServletConfiguration:

@Bean
@ConditionalOnMissingBean
public DispatcherServlet dispatcherServlet() {
    DispatcherServlet servlet = new DispatcherServlet();
    servlet.setDispatchOptionsRequest(true);
    return servlet;
}

@Bean
public DispatcherServletRegistrationBean dispatcherServletRegistration() {
    DispatcherServletRegistrationBean registration =
        new DispatcherServletRegistrationBean(dispatcherServlet, "/");
    registration.setLoadOnStartup(1);
    return registration;
}

ServletRegistrationBean:
- 实现 ServletContextInitializer
- onStartup() 时注册 Servlet

3. Filter 注册

@Bean
public FilterRegistrationBean characterEncodingFilter() {
    FilterRegistrationBean registration =
        new FilterRegistrationBean<>();
    registration.setFilter(new CharacterEncodingFilter());
    registration.addUrlPatterns("/*");
    registration.setOrder(1);
    return registration;
}

原理:
- FilterRegistrationBean implements ServletContextInitializer
- onStartup() 时注册 Filter
- 通过 Ordered 控制顺序

4. 容器切换（Jetty/Undertow）

切换到 Jetty:
1. 排除 Tomcat starter
   <exclusion>
       <groupId>org.springframework.boot</groupId>
       <artifactId>spring-boot-starter-tomcat</artifactId>
   </exclusion>

2. 添加 Jetty starter
   <dependency>
       <groupId>org.springframework.boot</groupId>
       <artifactId>spring-boot-starter-jetty</artifactId>
   </dependency>

原理:
- ServletWebServerFactoryAutoConfiguration
- @ConditionalOnClass({ Jetty.class })
- 创建 JettyServletWebServerFactory

六、Actuator 原理

1. Endpoint 实现

@Endpoint(id = "health")
public class HealthEndpoint {

    @ReadOperation
    public Health health() {
        return healthIndicator.health();
    }
}

注解类型:
- @Endpoint：定义端点
- @ReadOperation：GET 请求
- @WriteOperation：POST 请求
- @DeleteOperation：DELETE 请求

2. HealthIndicator 机制

HealthIndicatorAutoConfiguration:

@Bean
@ConditionalOnMissingBean
public DataSourceHealthIndicator dataSourceHealthIndicator() {
    return new DataSourceHealthIndicator(dataSource);
}

HealthIndicator 实现:
public class DataSourceHealthIndicator implements HealthIndicator {

    @Override
    public Health health() {
        try {
            // 执行验证查询
            jdbcTemplate.queryForObject(validationQuery);
            return Health.up().build();
        } catch (Exception e) {
            return Health.down().withException(e).build();
        }
    }
}

3. 端点暴露配置

management.endpoints.web.exposure.include=health,info,metrics
management.endpoints.web.exposure.exclude=env

EndpointMapping:
- /actuator/health
- /actuator/info
- /actuator/metrics

安全控制:
- management.endpoint.health.show-details=when-authorized
- 需要 authorized 角色才能查看详情

七、SpringBoot 与 Spring 的区别

1. 启动方式对比

传统 Spring:
1. 配置 web.xml
   - DispatcherServlet
   - ContextLoaderListener
2. 配置 applicationContext.xml
   - Bean 定义
   - 依赖注入
3. 部署到外部 Tomcat

SpringBoot:
1. main() 方法启动
2. @SpringBootApplication
3. 内嵌容器自动启动
4. 自动配置生效

2. Bean 注册方式对比

传统 Spring:
<bean id="userService" class="com.example.UserService">
    <property name="userRepo" ref="userRepository"/>
</bean>

SpringBoot:
@Service
public class UserService {
    @Autowired
    private UserRepository userRepo;
}

或:
@Bean
public UserService userService() {
    return new UserService(userRepository());
}

3. 配置管理对比

传统 Spring:
<context:property-placeholder location="classpath:config.properties"/>
<bean id="dataSource" class="...">
    <property name="url" value="${jdbc.url}"/>
</bean>

SpringBoot:
# application.yml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/mydb

@ConfigurationProperties(prefix = "spring.datasource")
public class DataSourceProperties {
    private String url;
}

4. 依赖管理对比

传统 Spring:
- 手动管理所有依赖版本
- 需要确保版本兼容
- 可能出现版本冲突

SpringBoot:
- spring-boot-starter-* 统一管理
- 版本由 spring-boot-parent 决定
- 自动解决版本兼容

八、面试高频问题

Q1: SpringBoot 自动配置如何实现？

回答要点:

1. @EnableAutoConfiguration
   - @Import(AutoConfigurationImportSelector)

2. SpringFactoriesLoader
   - 加载 META-INF/spring.factories
   - 获取自动配置类列表

3. 条件注解过滤
   - @ConditionalOnClass
   - @ConditionalOnBean
   - @ConditionalOnProperty
   - @ConditionalOnMissingBean

4. ConfigurationClassPostProcessor
   - 解析配置类
   - 注册 BeanDefinition

示例:
DataSourceAutoConfiguration
- 存在 DataSource.class
- 存在连接池依赖
- 配置了 spring.datasource.url
- 没有 custom DataSource
→ 自动创建 HikariDataSource

Q2: SpringBoot 启动流程？

回答要点:

1. new SpringApplication()
   - 推断应用类型（Servlet/Reactive/None）
   - 加载 Initializer 和 Listener
   - 推断主类

2. run()
   - 准备 Environment
   - 创建 ApplicationContext
   - prepareContext()
   - refreshContext()（核心）
   - 发布事件

3. refresh()
   - 执行 BeanFactoryPostProcessor
   - 自动配置生效
   - 注册 BeanPostProcessor
   - 初始化 Bean
   - 启动内嵌容器

Q3: Starter 原理？

回答要点:

1. Starter 结构
   - starter：依赖传递
   - autoconfigure：自动配置

2. 工作机制
   - 引入 starter → 带入依赖
   - 依赖包含 autoconfigure
   - spring.factories 定义配置类
   - 条件注解控制生效

3. 自定义 Starter
   - 创建 autoconfigure 模块
   - 编写配置类 + 条件注解
   - 编写 spring.factories
   - 创建 starter 模块依赖 autoconfigure

Q4: 内嵌容器原理？

回答要点:

1. 容器工厂
   - TomcatServletWebServerFactory
   - JettyServletWebServerFactory
   - UndertowServletWebServerFactory

2. 启动时机
   - onRefresh() 阶段
   - createWebServer()

3. Servlet 注册
   - ServletContextInitializer
   - DispatcherServletRegistrationBean
   - onStartup() 注册 Servlet

4. 切换容器
   - 排除默认 starter
   - 引入其他容器 starter
   - @ConditionalOnClass 自动选择工厂
